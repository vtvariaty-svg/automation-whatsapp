CONTRATO EXTERNO DISPONÍVEL NO NFE_WEB
Base conceitual da API externa já existente:
- POST /api/v1/external/nfe/issue
- GET /api/v1/external/nfe/id/:invoiceId/status
- GET /api/v1/external/nfe/ref/:externalReferenceId/status

Autenticação:
- Authorization: Bearer <API_KEY_M2M>

Header obrigatório para emissão:
- Idempotency-Key

Payload de emissão esperado:
{
  "external_reference_id": "string-obrigatoria",
  "company_id": "uuid-da-empresa",
  "natureza_operacao": "string",
  "customer": {
    "document": "string",
    "name": "string",
    "email": "string-opcional",
    "address": {
      "street": "string",
      "number": "string",
      "district": "string",
      "city": "string",
      "state": "string",
      "zipCode": "string"
    }
  },
  "items": [
    {
      "codigo_produto": "string",
      "descricao": "string",
      "quantidade": 1,
      "valor_unitario": 100.5
    }
  ]
}

Response típica de sucesso:
{
  "request_id": "string",
  "idempotency_key": "string",
  "status": "AUTHORIZED",
  "invoice_id": "string",
  "external_reference_id": "string",
  "protocol": "string-opcional"
}

Comportamentos importantes da API externa:
- Idempotency-Key igual + mesmo payload => replay seguro/cache
- Idempotency-Key igual + payload diferente => erro
- external_reference_id duplicado => conflito de negócio
- 408/429/5xx devem ser tratados como transitórios
- request_id deve ser preservado/logado para rastreabilidade
